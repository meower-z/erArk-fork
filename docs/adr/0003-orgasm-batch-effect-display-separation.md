# ADR-0003: 高潮批结算——效果全结算、显示只取代表;寸止判定合并到窗口末

日期:2026-07(自 openspec `h-orgasm-settlement` 蒸馏;实现载体 `mod/local_h_orgasm_batch_fix` + `local_orgasm_settle_edge_fix`,当前禁用)

## 决策

1. **效果与显示分离**:一次结算内同角色的全部高潮事件是一个原子批。每个产生的行为 ID 按出现次数各结算一次效果(不丢属性结算);显示上每部位只出最强一条,代表部位 ≤3 用完整地文,其余按强度分组汇总为一行,人力发电提示聚合成一条(数值为批总和)。
2. **边界顺序**:力竭/HP 中断必须等批内全部效果与其直接派生输出(奶/尿等)完成后才执行;批内产生的行为不许残留到下一次 update 形成"迟到的小绝顶"第二波。
3. **寸止窗口化**:寸止跨级在玩家动作窗口内静默累计,窗口末每角色至多一掷;失败当场原子释放全部累计并在同窗口完成派生(刻印/自动素质)结算,不许漏到下一次点击开头。
4. **主循环接管方式**:窗口末钩子通过 mod 替换 `character_behavior.init_character_behavior` 的组件私有副本实现,核心文件零 diff;组件禁用即恢复原行为。

## 后果

多部位/多重高潮的可读性大幅提升且数值不缩水。代价是批状态需要暴露给依赖组件(如群交寸止释放)防双重 flush;替换主循环的副本在上游主循环变动时需要同步维护——这是该组件禁用状态下重新启用前必须重新核对的点。
