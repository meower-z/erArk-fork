# 玩家可见信息重构简述

状态：**已暂缓（2026-07-14）**。短期不投入证据收集或实现，本文仅保留计划与收益说明。

## 现状

口上、地文、提示、事件和状态变化，都是“刚发生、应按顺序告诉玩家的信息”，但现在没有统一负责人。各功能既生成内容，又选择 Tk/Web 路径。Web 还分成历史、实时消息、对话框、弹窗和状态浮字，分别发送、清空或读后删除。同一内容可写入多处，顺序由调用点、清空和等待共同决定。时停会回拨游戏时间，Socket 消息也没有浏览器全序。显示错误常需跨口上、结算、面板、后端和前端排查，容易重复、遗漏或错序。

## 重构计划

新增一个只管理时间序玩家可见信息的 module。所有来源统一 `publish(fact)`；module 固化事实并分配不会回退的进程内序号。运行时只选择 Tk 或 Web adapter，继续投影到现有路径。面板、按钮、输入、等待、清屏和发送时机仍归原流程；现有 Tk/Web 行为和 Web payload 保持不变，不兼容 mod。

先记录当前顺序和所有写入、清空点，再做 shadow 对比；之后一次只切换“一个来源的一个输出位置”，可独立回滚，最后删除旧分支。

## 收益

信息分类和进程内顺序有单一负责人，Tk/Web 差异集中在 adapter。以后能直接区分“事实生成错”还是“某端显示错”，减少跨层排查和重复分支，让双端行为可以逐项比较、验证和回滚。
