## Context

`talk_common_judge()` 为纸娃娃地文选择通用组件时固定以玩家角色计算前提。NPC 触发时，它会先把玩家的 `target_character_id` 改成该 NPC，但调用结束后不恢复；处理部位短词时，它还会通过 `part_dict["A"] += common_s_A_list` 修改从全局配置取得的列表。两处写入都服务于一次渲染，却会影响之后的游戏状态或候选权重。

## Goals / Non-Goals

**Goals:**

- 让临时交互目标只在一次通用口上展开期间生效，并在任何退出路径恢复。
- 让每次候选组合都从未被渲染过程修改的配置构造。
- 分别验证两个状态生命周期，避免一个修复掩盖另一个。

**Non-Goals:**

- 不改变纸娃娃地文的选择概率、前提语义或角色格式化规则。
- 不处理独立纸娃娃标记的来源传递；该修复属于独立候选分支。
- 不重构整个口上配置结构或随机选择系统。

## Decisions

### 用作用域恢复临时玩家目标

在进入需要 NPC 目标的通用展开前保存玩家原目标，在 `try/finally` 边界内临时设置，并在 `finally` 恢复。该边界同时覆盖正常返回、替换回调异常和前提计算异常。只在现有逻辑确实需要改目标时进入作用域，保持玩家触发和不在同场景的行为不变。

备选方案是在每个返回点手工恢复，但异常和未来新增返回点容易再次泄漏；把目标改写保留为永久状态则违背渲染只读游戏状态的要求。

### 从全局配置复制候选列表再组合

读取部位字典时只复制本次需要扩充的列表，并用新列表拼接 `common_s_A_list`。不深拷贝整个通用口上注册表，因为只需隔离会发生拼接的单层候选列表。

备选方案是在函数结束时删除追加项，但重复元素和异常退出会使回滚长度难以可靠判断；全量深拷贝则扩大成本和改动范围。

### 两个修复保持独立任务

目标恢复与候选复制共享“渲染不得泄漏状态”的总要求，但写入对象、失败表现和测试夹具不同。任务和提交应分别验证，便于独立回滚。

## Risks / Trade-offs

- [部分调用依赖永久目标改写] → 先盘点 `talk_common_judge()` 后续消费者，并用连续绘制测试证明后续 UI/AI 不需要该泄漏才能工作。
- [浅复制遗漏其他嵌套写入] → 在实现前记录所有对 `part_dict` 及其列表的写操作，并用重复调用前后配置快照验证。
- [异常路径未进入恢复边界] → 让临时赋值和所有通用替换逻辑处于同一 `try/finally` 中，并注入异常验证恢复。
