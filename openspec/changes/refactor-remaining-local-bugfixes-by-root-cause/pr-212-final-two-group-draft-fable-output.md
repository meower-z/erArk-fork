修复苦痛快感化：负向苦痛不再被改道，所有正向苦痛来源统一转换为心理快感
TITLE_END
BODY_BEGIN
## 问题

开启催眠效果「苦痛快感化」后，存在两类可见的错误行为：

1. **负向苦痛被错误改道。** 苦痛的负向变化（例如绝顶后苦痛大幅回落）也被送进心理快感结算，导致角色的心理快感被大额负值反向清空，甚至从满级直接归零。
2. **部分正向苦痛来源完全没有被转换。** 小苦痛 / 中苦痛 / 大苦痛，以及连续额外绝顶产生的额外苦痛，是直接累加 `status_data[17]` 的，不经过通用状态结算入口，因此即使开启了苦痛快感化，这些苦痛仍按原样结算，玩家看不到任何转换。

## 原因

苦痛快感化的判断原本只写在 `base_chara_state_common_settle` 的 state 17 分支里，且不区分正负：

- 负值也会走转换分支，被当作心理快感的负向变化结算，这是第一类错误的来源。
- 而小/中/大苦痛与额外绝顶这几处直接写 `status_data[17]`，根本不进这个入口，转换判断对它们不生效，这是第二类错误的来源。

只在通用入口加一个正值判断能修复第一类，但修不了第二类。

## 修复

在 `common_default.py` 中新增一个很窄的统一转换边界 `try_settle_pain_as_pleasure(character_id, pain_value, ...)`：

- 入参是**来源自身修正全部完成后**的有符号最终苦痛值。
- 值 ≤ 0，或未开启苦痛快感化时，返回 `False`，来源照常写入苦痛（state 17）。负向苦痛因此留在苦痛本身，修复第一类错误。
- 正值且开启时，**恰好一次**调用现有的通用结算 `base_chara_state_common_settle(..., state_id=23, ability_level=ability[36], tenths_add=False, ...)` 并返回 `True`。helper 自己不计算心理快感的能力系数，能力加成只在这一次通用结算内部应用，不存在重复计算。
- 返回 `True` 的含义是「转换路径已接管」：即使 state 23 结算因睡眠、无意识等条件提前返回，来源也不会再回落写入 state 17，避免出现苦痛 / 心理快感双重记账。

调用点共五处，全部复用同一 helper：

- `base_chara_state_common_settle` 的 state 17 分支：在既有修正之后调用，正值转换、负值留在苦痛。
- 小苦痛 / 中苦痛 / 大苦痛：在各自来源公式算出最终值之后调用，转换成功则不再直接写 state 17，修复第二类错误。
- 连续额外绝顶：额外苦痛同样交给 helper；无论是否转换，恐怖照常结算、连续计数照常清零，提示文本按实际结算显示「心理快感和恐怖」或「苦痛和恐怖」。

通用路径原有的连续结算倍率等调整逻辑没有改动；helper 与通用结算之间没有递归环。

REVIEW_REPLY_BEGIN
「只转换正值」这个方向是对的，负向苦痛确实不该被改道，这次已经改成正值才转换。不过只在通用结算的 state 17 分支里加判断还不够：小/中/大苦痛和连续额外绝顶是直接写 `status_data[17]` 的，不经过这个分支，开了苦痛快感化也不会被转换。所以保留了一个很窄的 helper 作为这几处的统一入口。关于重复计算的担心：helper 自己不算心理快感的能力系数，只是恰好一次调用现有的 state 23 通用结算（`ability_level=ability[36]`），能力加成只在那一次结算里应用，不会算两遍。
