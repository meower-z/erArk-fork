## 玩家可见问题

角色处于心控「苦痛快感化」状态时，执行会降低苦痛的指令（如 `[4103]体控-强制高潮`），结算会出现巨额负向心理快感。实测中一次强制高潮直接把心理快感从 lv10 清空到 0（`心理快感 -272586`），而苦痛本身反而没有下降（`苦痛 +3811`）。玩家看到的效果与「苦痛转化为快感」的设计完全相反。

## 原因

`Script/Settle/common_default.py` 的通用状态结算里，苦痛（state 17）在「苦痛快感化」生效时会整体改道为心理快感（state 23）结算，但改道条件没有判断变化量的正负。于是本应减少苦痛的负向增量也被改道，变成了一次巨额负向的心理快感结算。

## 修复

按 maintainer 意见，不再单独构建转换函数（单独函数会把心理快感的能力加成重复计算两遍），只在现有通用结算分支上增加 `final_value > 0` 判断：

- 最终为正的苦痛增量：仍走原有递归 state 23 结算，转化为心理快感，能力加成只计算一次；
- 最终为零或负的苦痛变化：留在原有 state 17 路径，正常增减苦痛。

改动仅此一处、两行替换。

## 验证

两侧从同一个冻结的 No.99 存档、相同种子启动真实 Tk 客户端，经标题页与存档页加载后执行一次 `[4103]体控-强制高潮`，逐页确认到完整结算：

- 修复前（`abebf33`）：`心理快感 -272586 (lv10→0)`，`苦痛 +3811`——苦痛未降，心理快感被清空。
- 修复后（`6864d4c`）：`苦痛 -30397 (lv7→4)`，`心理 +168`，`心理经验 +3`——苦痛正常下降。其中 `心理 +168` 与 `心理经验 +3` 来自普通 state 17 路径本就包含的 `extra_feel_settle`（受虐相关能力派生的心理快感与经验）：修复前负向变化被整体改道到心理快感结算，根本走不到这一步；修复后负向变化重新落回普通苦痛路径，这套原有结算才随之正常出现，说明原有普通结算被完整保留，不是转换错误残留。
