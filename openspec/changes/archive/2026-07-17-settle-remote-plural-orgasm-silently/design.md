## Context

`character_get_second_behavior()` 只把带 `997` 的行为加入角色的 `must_settle_second_behavior_id_list`。远程二段行为路径只执行必须显示和必须结算列表，然后返回；未进入任一列表的行为继续留在 `second_behavior` 队列。普通部位绝顶已带 `997`，而 `plural_orgasm_2` 至 `plural_orgasm_11` 没有，因此远处产生的多重绝顶效果会延迟到角色重新进入玩家附近时才结算并显示旧口上。

## Goals / Non-Goals

**Goals:**

- 让十个多重绝顶行为沿用现有远程静默结算规则。
- 在远处完成其数值效果并清除队列，不显示远程多重绝顶口上。
- 保持玩家附近的原有显示和结算行为不变。

**Non-Goals:**

- 不重构口上、队列、结算或 Tk/Web 绘制系统。
- 不修改普通部位绝顶、寸止或群交参与者规则。
- 不把 `997` 加到会在效果函数中直接绘制文本的 `extra_orgasm`、`b_orgasm_to_milk` 或 `u_orgasm_to_pee`。

## Decisions

### 复用 `997` 配置语义

只在十个 `plural_orgasm_N` 行追加 `997`。配置加载器和远程二段行为路径已经共同定义了“必须结算但不必须显示”的行为；使用该现有接口比增加新的远程过滤分支更小，也与普通部位绝顶保持一致。

备选方案：在远程路径中按行为名前缀特殊处理多重绝顶。拒绝，因为它重复了 `997` 已有的声明式职责，并把领域列表写进 Python 控制流。

### 保持直接绘制的衍生效果在范围外

`extra_orgasm`、喷乳和漏尿的效果函数会自行调用绘制接口。给它们添加 `997` 会让数值在远处结算，但仍可能打印远程文本，因此不能作为同一个配置修复提交。

备选方案：同时改造这些效果函数的显示。拒绝，因为那会把配置缺失修复扩大为显示架构变更，无法再称为 997-only。

### 用真实远程队列生命周期验证

自动化回归必须经过配置加载语义、`character_get_second_behavior()` 和远程 `second_behavior_effect()`，证明基线会留下行为，候选会静默结算、清除并至少实际应用一项 409/301-306 配置效果的数值变化。Tk A/B 使用同一存档和同一路线，必须先捕捉基线的延迟口上，再证明候选同一路线不再显示旧口上。

## Risks / Trade-offs

- **[生成物与源 CSV 不一致]** → 运行项目配置构建并只保留由这十行变化产生的必要生成物。
- **[把静默误写成不结算]** → 自动化同时断言效果值变化、行为归零和无口上调用。
- **[同房间显示被意外压制]** → 增加同房间逆向用例，确认仍调用原有口上并结算。
- **[群交发现意外依赖滞留行为]** → 在诗怀雅类路线中确认角色靠近后的发现群交仍按原规则发生；若失败则停止候选并重新审查玩法语义。
- **[截图路线混入本地 mod 行为]** → 从相同 `upstream/master` 基线建立 A/B，禁用承担相同职责的本地批处理 mod，并记录版本、存档和操作。
