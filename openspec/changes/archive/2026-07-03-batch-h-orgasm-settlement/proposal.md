## Why

H 结算中的多重绝顶现在会把同一部位的多个绝顶逐条压入二段行为，导致重复口上、冗长输出，并且可能在二段结算尚未完成时因体力耗尽提前结束 H。人力发电室还会逐条显示每个部位的发电量，最后再显示多重绝顶发电量。需要把一次结算周期内的绝顶视为同一个批次，保证显示更聚焦、效果归属更完整、H 内属性归属一致。

本次修复需要以 mod 形式实现，避免直接修改游戏核心文件。

## What Changes

- 在 `mod/local_bugfix` 中新增 H 绝顶批处理脚本，通过 mod 系统替换必要函数，不直接修改 `Script/Design` 或 `Script/UI` 的核心文件。
- 将 NPC 的 H 绝顶结算改为批次化处理：先收集本次结算周期内各部位触发的绝顶行为和最高强度，再统一显示和结算。
- 同一部位在同一批次中只展示最高强度的一段绝顶口上；不同强度的二段效果仍结算，但同一个行为 ID 保持原版 0/1 开关语义，不额外变成次数结算。
- 多重绝顶时先展示原版“几重绝顶”和对应口上，然后只遍历一次绝顶部位：最重要的 3 个部位播放原格式的部位强度提示与口上，其余部位按强度分组压缩为一行短强度文本，避免重复信息。
- 控制代表部位黄色强度提示与其后口上之间的空行数量，避免紧凑显示时出现过多空白。
- 修复多重绝顶提示和口上出现后，旧二段行为队列残留导致后续更新又出现单独部位绝顶提示的问题。
- H 体力耗尽导致的中断判定延后到绝顶批次结算完成之后，确保绝顶导致的属性变化全部算作 H 内结算。
- 人力发电室中保持原发电结算和数值不变，但同一批多重绝顶只显示一条合计发电提示；提示文本沿用原版多重绝顶发电文本，只替换电量数字。
- 修复本地批处理实现中循环变量遮蔽翻译函数 `_` 导致后续成就文本调用出现 `TypeError: 'int' object is not callable` 的运行时错误。
- 不改变 CSV 行为 ID 的外部含义；复用现有二段行为、口上和效果数据。
