# 局部时长文案边界复核

## 已核实事实

- 上游 `settle_behavior.handle_settle_behavior()` 在同一个面板尾部按同一个角色局部 `add_time` 二选一追加文本：普通输出为“X分钟过去了”，NPC 对玩家的交换输出为“该行动将持续X分钟”。
- `add_time` 由结算时刻减去角色行为开始时刻得到；正常路径传入行为结束时刻。因此后一条文本也是结算阶段的角色局部时长说明，并不是行动选择前的独立预览。
- 两种文本在 Web 中原本都随 `now_text` 写入 `cache.web_instruct_texts`，并通过 `emit_realtime_text(..., "instruct")` 推送。
- 合并后的唯一“X分钟过去了”由最外层 `game_update_flow()` 在全部角色结算后按游戏时钟净差生成。为保持旧 Web 的文本类别和回溯行为，这一条仍需写入同一个缓存并使用同一种实时推送类型；Tk 继续使用 `io_init.era_print()`。

## 候选边界

1. 保留“该行动将持续X分钟”：生产 diff 为 `a=13, b=10, S=7, U=0`，penalty `30`。角色面板仍保留一种角色局部时长句。
2. 同时移除两种角色局部时长句：生产 diff 为 `a=10, b=10, S=7, U=0`，penalty `27`。角色面板只显示角色变化，唯一实际经过时间由最外层更新显示。

## 保持不变

- 不改变游戏时钟推进、角色行为时长、结算顺序、数值或事件。
- Web 仍在原有 `instruct` 文本回溯中记录时间句，只从按角色多条改为最外层一条。
- 不提交 `local_tests/`。

## 证据要求

- 修复前使用原始群交问题截图：同屏多个具名角色自慰/结算块，并有多条字面完全相同的“5分钟过去了”。
- 修复后使用已有群交候选截图：多个角色结算块保留，但没有角色级时间句。
- 最后一张使用已有返回主界面截图：只显示一条合并后的“X分钟过去了”。
- 删除另一种局部时长措辞本身不重跑 Tk。

## 复核结果

- Fable 代码边界复核：`PASS`。选择候选 2，同时删除两种角色局部时长句；Web 保留原 `instruct` 回溯与推送通道。
- 本地聚焦回归：`11 passed`；生产文件与本地测试通过 `py_compile` 和 `git diff --check`。
- Fable 图片复核：`NEEDS_REVISION`。原始多条“5分钟过去了”图和现有修复后群交图可用；现有最终帧来自仍显示“该行动将持续”的旧候选，不能证明最终代码的合并行状态。按用户要求不重跑 Tk，因此第三张证据暂缺。
