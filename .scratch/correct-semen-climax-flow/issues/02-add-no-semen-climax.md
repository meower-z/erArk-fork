# 02 — 为无精液高潮建立独立结算行为

**What to build:** 当玩家射精槽达到高潮阈值、但基础精液与临时精液合计不超过 2 ml 时，系统把结果作为“无精液高潮”完整结算：玩家发生高潮并承担属于高潮本身的后果，但不进入射精对象或部位选择，不产生射精统计、精液目标效果或普通射精口上。

**Blocked by:** None — can start immediately

**Status:** ready-for-agent

- [ ] 共享玩家高潮入口在合计精液不超过 2 ml 时登记专用二段行为 `p_no_semen_climax`，不再登记普通小量射精行为。
- [ ] 无精液高潮不打开射精对象或部位选择面板，并使用专用系统文本明确表达“发生高潮但没有精液排出”。
- [ ] 专用行为通过既有行为、效果和系统二段口上数据声明，不新增专用 Python 结算函数，也不新增依赖。
- [ ] 专用行为只保留效果 231、232、411、501、997：小量体力与气力消耗、隐奸高潮暴露判定、双方插入位置清理和必须执行二段结算。
- [ ] 专用行为不包含效果 221、225、415 或目标精液经验调整，不增加射精经验、射精次数、目标润滑、人力发电、欲情减半或目标精液经验。
- [ ] 无精液高潮不产生精液污浊、射精位置、受孕、避孕套或射精成就结算。
- [ ] 无精液高潮完成后，玩家射精槽和 `endure_not_shot_count` 均清零，停止忍耐和普通 H 结束释放不会对同一次高潮重复触发。
- [ ] 合计精液超过 2 ml 时，普通小量、大量和超大量射精选择及其既有效果保持不变。
- [ ] 自动回归测试复用既有 near-real 无 GUI 引导，从共享玩家高潮判断边界验证行为登记、面板是否调用、射精槽、忍耐次数及正量精液控制组。
- [ ] 二段行为测试验证保留的体力/气力消耗和插入位置清理；隐奸暴露只在现有引导能确定性观察时直接断言，否则通过稳定的既有子系统边界确认调用。
- [ ] 负向测试确认射精经验/次数、目标润滑与精液经验、污浊、射精位置、受孕/避孕套、成就、人力发电和欲情减半均不发生；必要时只在既有子系统边界使用 spy，不为测试新增生产接口。
- [ ] 使用同一存档、设置和高潮触发操作捕获独立 Tk 前后证据：修复前出现射精对象/部位选择，修复后直接显示专用无精液高潮结果。
- [ ] 数据按仓库正常构建流程生成并验证，且最终 diff 不包含动态事件高潮、避孕套无效选择、群交旁观者、深喉位置改写或角色专属口上修复。
- [ ] 若实施时发现规格列出的正常玩法路径绕过共享玩家高潮入口，停止并报告边界不符，不静默扩大本票范围。
