# 03 — 无精液时隐藏衣柜射精选项

**What to build:** 玩家检查宿舍或更衣室中的干员衣柜时，若基础精液与临时精液合计不超过 2 ml，菜单不再显示“用衣服冲，射在上面”。其他可用的嗅闻、收藏和返回操作保持原样；精液超过阈值时，既有衣柜射精流程仍可进入。

**Blocked by:** None — can start immediately

**Status:** ready-for-agent

- [ ] 衣柜操作菜单复用既有合计精液前提，合计精液不超过 2 ml 时省略“用衣服冲，射在上面”，不复制或改写 2 ml 判断公式。
- [ ] 合计精液超过 2 ml 时，“用衣服冲，射在上面”继续显示并进入既有衣物种类选择和射精流程。
- [ ] 隐藏射精选项时，“把内衣拿起来闻一闻味道”和“返回”仍然显示且可用。
- [ ] 衣柜内存在内裤或袜子时，相应的偷取选项在射精选项隐藏后仍然显示且可用。
- [ ] 守卫适用于共享菜单构造所覆盖的宿舍衣柜与更衣室衣柜，不改变衣柜发现、干员选择、衣物名称、现有污浊量显示或返回导航。
- [ ] 自动回归测试复用既有 near-real 无 GUI 引导，构造包含衣物的真实衣柜并捕获玩家可见菜单文本；无精液用例断言射精选项缺失且其他适用选项存在，正量精液控制组断言射精选项存在。
- [ ] 自动测试至少覆盖共享菜单分支中的一个地点；仅当实施检查发现宿舍和更衣室存在不同守卫逻辑时才增加第二个地点用例。
- [ ] 使用同一无精液存档、同一干员衣柜和同一设置捕获独立 Tk 前后证据：修复前射精选项存在，修复后该选项消失且其他菜单操作仍可见。
- [ ] 改动只处理衣柜菜单可用性，不改变无精液高潮、通用射精返回量、嗅闻选项的衣物条件或多件内裤/袜子的收藏行为。
- [ ] 最终 diff 不引入新抽象或依赖，并通过项目标准和本票行为范围两轴审查。
